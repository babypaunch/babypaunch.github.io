시작은 웹페이지 캡처였다.

웹프로젝트를 만들고 나면 모바일, 태블릿과 PC 화면을 반복해서 확인해야 했다.

매번 같은 화면 크기와 검사 기준을 설명하기 귀찮아서 Codex가 다시 사용할 수 있는 작업 지침을 하나 만들었다.

이제 화면을 확인하는 일이 조금 편해졌다고 생각했다.

그런데 곧 AI가 읽어야 할 도구 설명이 너무 많다는 안내가 나타났다.

일을 줄이려고 도구 하나를 추가했는데, 이번에는 그 도구들을 관리할 일이 생긴 것이다.

<p class="article-question">AI 도구는 설치해 두기만 하면 계속 같은 방식으로 잘 작동할까?</p>

## 같은 도구가 여러 자리를 차지하고 있었다

먼저 실제로 사용할 수 있는 도구 목록을 살펴봤다.

기능은 같은데 설치된 위치만 다른 항목이 여러 개 발견됐다.

AI는 작업을 시작하기 전에 어떤 도구를 쓸 수 있는지 확인하므로, 이런 중복 설명도 작업 공간을 차지한다.

파일을 무턱대고 지우지는 않았다.

사용할 경로 하나를 남기고 겹치는 경로만 비활성화했다.

**쉬운 설명: 같은 드라이버가 공구함 여러 칸에 들어 있었다면 하나만 꺼내기 쉽게 두고 나머지는 보관한 셈이다.**

## 설치 목록보다 사용 흔적이 궁금해졌다

중복을 정리하고 나니 어떤 도구를 실제로 쓰고 있는지가 궁금해졌다.

설치됐다는 사실과 유용하게 사용됐다는 사실은 다르다.

그래서 이미 남아 있던 작업 기록에서 도구를 호출한 흔적을 모아 보는 기능을 기존 도구 목록에 덧붙였다.

새 서버를 만들거나 모든 행동을 감시하는 프로그램을 계속 실행하지는 않았다.

필요할 때 최근 기록을 읽어 사람이 볼 보고서를 만드는 정도면 충분했다.

기록에서 찾지 못한 도구에는 `미사용` 대신 `사용 미확인`이라고 표시했다.

한 달에 한 번 쓰는 배포 점검 도구는 매일 쓰는 편의 기능보다 호출 횟수가 적어도 더 중요한 순간이 있기 때문이다.

## 사용 횟수만으로는 부족했다

며칠 뒤에는 또 다른 문제가 보였다.

오늘 잘 작동한 도구가 다음 업데이트 뒤에도 같은 상태라는 보장이 없었다.

그래서 이름만 기록하지 않고 설치 버전과 파일이 달라졌는지 확인할 수 있는 값도 함께 남겼다.

**쉬운 설명: 공구 이름만 적는 대신 어느 모델인지와 내용물이 바뀌지 않았는지 확인할 봉인 번호까지 기록한 것이다.**

변경 이력은 비공개 Git 저장소에 두고, 실제 복구에 필요한 파일 묶음은 별도 백업으로 보관했다.

Git은 언제 무엇이 바뀌었는지 찾는 데 좋고, 백업은 다른 PC에서 실제 파일을 되살리는 데 적합했다.

계정 토큰, 로그인 기록과 개인 경로는 어느 쪽의 공개 가능한 기록에도 넣지 않았다.

비공개 저장소라고 해도 한번 들어간 비밀값은 나중에 완전히 지우기 어렵기 때문이다.

## 자동 검사도 마지막 판단은 아니었다

관리 기능을 만들고 자동 검사를 실행했더니 일부 도구가 없다는 결과가 나왔다.

하지만 실제 파일과 등록 상태를 따로 확인하니 Windows 경로의 띄어쓰기를 검사기가 잘못 읽은 경우였다.

검사 결과만 믿고 다시 설치했다면 멀쩡한 설정을 오히려 바꿀 수 있었다.

**쉬운 설명: 주소 자동 검사기가 띄어쓰기를 잘못 읽었다면 집이 사라졌다고 결론 내리기 전에 실제 주소부터 찾아봐야 한다.**

그래서 목록 확인, 파일 확인과 실제 실행 결과를 서로 다른 증거로 남겼다.

AI에게 검사를 맡겨도 무엇을 확인했고 무엇은 추정했는지 구분해야 했다.

## AI를 오래 쓸수록 관리 기준도 필요했다

처음에는 화면 캡처를 편하게 만들고 싶었을 뿐이었다.

그 일이 중복 도구 정리, 사용 흔적 확인과 업데이트 상태 기록으로 이어졌다.

도구가 많다는 사실 자체가 문제는 아니었다.

무엇을 왜 남겼는지 모르고, 언제 달라졌는지 확인할 방법이 없는 상태가 문제였다.

이제 새 도구를 설치하기 전에는 기존 기능과 겹치는지 먼저 보고, 업데이트 전에는 현재 상태를 기록한다.

호출 횟수가 0이라는 이유만으로 자동 삭제하지 않고, 문제가 생기면 변경 이력과 백업을 함께 확인한다.

AI가 일을 대신할수록 사람에게 아무 일도 남지 않는 것은 아니었다.

사람이 직접 해야 할 일은 반복 작업에서 관리 기준을 정하는 쪽으로 옮겨 갔다.

## #AI프롬프트제공

다음 프롬프트는 사용하는 AI 도구의 중복, 사용 흔적과 업데이트 상태를 안전하게 점검할 때 사용할 수 있다.

비밀번호·API 키·토큰·개인정보는 프롬프트에 입력하지 않는다.

<section class="article-ai-prompt" data-no-translation markdown="1">

```text
[AI 도구 설정 폴더]에 설치된 Skill, Plugin과 MCP를 점검해줘.

기존 목록이나 관리 스크립트가 있으면 먼저 재사용하고,
같은 기능이 여러 경로에 중복 설치됐는지 찾아줘.
삭제하거나 비활성화하기 전에는 각각의 출처와 현재 사용 경로를 구분해 보고해줘.

보존된 최근 [30]일 작업 기록에서 확인 가능한 사용 흔적을 집계해줘.
직접 호출, 코드 안에 적힌 호출 추정과 지침을 읽은 기록을 서로 구분하고,
근거가 없는 항목은 '미사용'이 아니라 '사용 미확인'으로 표시해줘.

각 도구의 설치 버전과 파일 변경 여부를 다시 확인할 수 있는 기록을 만들어줘.
버전이 고정되지 않은 항목은 표시만 하고 내 승인 없이 업데이트하거나 삭제하지 마.

토큰, 환경 변수 값, 로그인 세션, 대화 원문과 사용자 절대 경로는 결과에서 제외해줘.
Git 변경 이력과 실제 복구용 백업의 역할을 나눠 제안하고,
목록 확인, 자동 검사, 파일 확인과 실제 실행 검증 결과를 구분해 보고해줘.
```
